# StageBook 数据库大作业验收说明

本文档面向课程老师/助教，用于在本地快速部署、运行并验收 StageBook 数据库大作业项目。

---

## 1. 项目简介

StageBook 是一个面向剧场演出的信息管理与个性化观演辅助系统。项目包含普通用户界面与管理员界面，主要围绕数据库中的剧目、场次、演员、剧院、餐馆、交通方案、用户偏好、观演计划、观演记录等数据进行展示和维护。

普通用户可以完成：

- 查看演出信息汇总
- 维护个人偏好画像
- 查看推荐剧目并加入观演计划
- 在观剧日历中管理计划状态
- 查看场景化行程辅助推荐
- 注销自己的账号

管理员可以完成：

- 查看整体剧目日历
- 新增、修改、删除剧目
- 新增、批量新增、修改、删除场次
- 新增和删除剧院、演员、餐馆、交通方案等基础数据
- 使用 SQL 展示台进行常用数据库检测

项目后端数据库使用 MySQL，前端可视化界面使用 Streamlit 实现。

---

## 2. 项目包结构说明

解压项目包后，通常可以看到以下文件或文件夹：

```text
stagebook_streamlit_app_login_modified/
├─ app.py                         # Streamlit 主程序
├─ main_code.sql                  # 数据库建表、视图、存储过程、测试数据等 SQL 脚本
├─ requirements.txt               # Python 依赖
├─ README.md                      # 本说明文件
└─ .streamlit/
   └─ secrets.example.toml        # 数据库连接配置模板，不包含真实密码
```

如果项目包中的文件名略有差异，请以实际解压后的文件为准，但核心运行文件为 `app.py` 和 `main_code.sql`。

## 3. 运行环境要求

建议使用以下环境进行验收：

- 操作系统：Windows 10 / Windows 11
- Python：3.9 及以上版本
- MySQL：8.0 及以上版本
- 浏览器：Chrome / Edge / Firefox 均可

需要提前确认：

1. MySQL 服务已经启动。
2. 本机能够通过 MySQL 用户名和密码正常连接数据库。
3. Python 和 pip 已正确安装。

在命令行中可分别检查：

```powershell
python --version
pip --version
mysql --version
```

---

## 4. 第一次运行前的准备步骤

### 4.1 解压项目包

将项目压缩包解压到本地目录，例如：

```text
D:\大学课程\大三下\数据库\stagebook_streamlit_app_login_modified
```

注意：路径中可以包含中文，但后续在 PowerShell 中进入目录时建议加英文双引号。

例如：

```powershell
cd "D:\大学课程\大三下\数据库\stagebook_streamlit_app_login_modified"
```

不要在 PowerShell 中使用 `cd /d`，这是 cmd 的写法。

---

### 4.2 安装 Python 依赖

进入项目根目录后执行：

```powershell
pip install -r requirements.txt
```

如果电脑中同时存在多个 Python 版本，也可以使用：

```powershell
python -m pip install -r requirements.txt
```

---

### 4.3 导入数据库脚本

请先在 MySQL 中导入项目提供的 `main_code.sql`。

方式一：使用 MySQL 命令行导入。

```powershell
mysql -u root -p < main_code.sql
```

输入本机 MySQL 密码后等待执行完成。

方式二：使用 MySQL Workbench / DataGrip / Navicat 等工具。

1. 打开数据库管理工具。
2. 连接本机 MySQL。
3. 打开 `main_code.sql`。
4. 执行整个 SQL 文件。

导入完成后，数据库中应包含本项目所需的表、视图、存储过程、触发器和测试数据。

如果 SQL 文件中已经包含 `CREATE DATABASE` 和 `USE` 语句，则直接执行即可；如果老师本机环境要求手动创建数据库，请创建与程序连接参数一致的数据库名，例如：

```sql
CREATE DATABASE stagebook DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE stagebook;
```

然后再执行 `main_code.sql`。

## 5. 数据库连接方式

本项目采用“自动配置优先，页面输入兜底”的方式连接 MySQL。

### 5.1 推荐验收方式：页面输入数据库密码

如果项目包中没有 `.streamlit/secrets.toml`，程序启动后会在页面侧边栏显示数据库连接参数输入区。

老师只需要填写或确认：

```text
host: localhost
port: 3306
user: root
password: 本机 MySQL 密码
database: stagebook
```

然后点击连接或刷新页面即可进入系统。

这种方式不需要学生提交真实数据库密码，适合验收环境。

---

### 5.2 可选方式：使用 secrets.toml 自动连接

如果希望运行后自动连接数据库，可以在项目根目录下创建：

```text
.streamlit/secrets.toml
```

内容示例：

```toml
[mysql]
host = "localhost"
port = 3306
user = "root"
password = "本机MySQL密码"
database = "stagebook"
```

注意：

- `secrets.toml` 中包含本机数据库密码。
- 学生提交项目时通常不应提交真实 `secrets.toml`。
- 项目包中保留 `secrets.example.toml` 作为模板即可。

## 8. 普通用户端验收路径

使用普通用户账号登录：

```text
Estelle / 123456
```

建议按以下顺序验收。

### 8.1 我的首页

进入系统后首先查看“我的首页”。

可检查内容：

- 首页是否为卡片化展示。
- 页面介绍是否面向用户，而不是操作说明式文案。
- 快捷入口是否可以跳转到对应页面。
- 是否没有显示异常代码或调试信息。

---

### 8.2 演出信息汇总

进入“演出信息汇总”。

可检查内容：

- 页面以剧目为单位展示，而不是简单数据库表格。
- 剧目标题后不应出现类似 `#17` 的内部编号。
- 点击或展开剧目后，可以看到对应场次详情。
- 场次详情中应包含时间、地点、价格、演员等信息。
- 页面不应显示 Python / HTML / Markdown 原代码。

---

### 8.3 用户偏好画像

进入“用户偏好画像”。

可检查内容：

- 可以新增偏好，例如演员、剧种、语言、区域等。
- 新增成功后会出现短暂成功提示。
- 已添加的偏好可以删除。
- 偏好变化后，推荐结果可以联动更新。

---

### 8.4 混合引擎推荐

进入“混合引擎推荐”。

可检查内容：

- 推荐结果以清晰卡片形式展示。
- 页面中不应出现“刷新画像推荐缓存”按钮。
- 剧目名称后不应显示内部编号。
- 点击“加入计划”后，该场次会进入观剧日历，状态为 `planned`。
- 同一剧目的同一场次不应被重复加入。
- 不同场次可以分别加入计划。

---

### 8.5 我的观剧管理

进入“我的观剧管理”。

可检查内容：

- 页面以彩色日历形式展示观剧计划和记录。
- 点击日期格子可以弹出相应管理区域。
- 可以添加计划。
- 可以新增观剧记录。
- 可以修改观演状态。
- 状态包括：
  - `planned`
  - `booked`
  - `watched`
  - `canceled`

状态联动规则：

- 设置为 `planned` 或 `booked`：保留在日历中。
- 设置为 `watched`：写入观剧记录，并以已观看状态体现。
- 设置为 `canceled`：从日历中移除，不再显示。
- 同一剧目的同一场次不能重复加入日历。

---

### 8.6 场景化行程辅助

进入“场景化行程辅助”。

可检查内容：

- 页面不再显示“原始行程辅助视图”。
- 行程推荐不仅显示剧院信息，还会明确对应哪个剧目和哪个具体场次。
- 从推荐页加入计划后，对应场次应出现在此页面。
- 取消计划后，对应内容应从此页面消失或不再作为有效计划展示。

---

### 8.7 注销账号

普通用户界面中提供注销账号操作。

可检查内容：

- 普通用户可以发起注销。
- 注销前有确认步骤。
- 注销后账号相关数据按系统设计处理，不能继续作为正常登录用户使用。

## 9. 管理员端验收路径

使用管理员账号登录：

```text
admin / StageBook123!
```

管理员界面名称为“演出信息管理”。

建议按以下顺序验收。

---

### 9.1 整体剧目日历

进入管理员端后查看整体剧目日历。

可检查内容：

- 所有演出场次按日期显示在日历中。
- 点击日期或场次可以查看对应演出详情。
- 详情中包含剧目、剧院、时间、演员等信息。
- 管理员可以从整体视图快速了解演出排期。

---

### 9.2 新增剧目

进入“新增剧目”相关功能区。

可检查内容：

- 新增剧目只负责剧目基本信息。
- 不在新增剧目中混入场次、剧院、演员等已拆分职责。
- 同一剧目不允许重复添加。
- 支持批量新增剧目。
- 剧目名称应统一、规整，后续可在下拉框中选择。

---

### 9.3 新增场次

进入“新增场次”相关功能区。

可检查内容：

- 新增场次只负责场次信息。
- 剧目从已有剧目下拉框中选择。
- 剧院从已有剧院下拉框中选择。
- 不重复展示已经确定的剧目信息。
- 支持批量新增场次。
- 新增成功后，用户端“演出信息汇总”和管理员“整体剧目日历”中可以看到新增内容。

---

### 9.4 修改演出信息

进入“修改信息”或对应维护区域。

可检查内容：

- 能修改剧目基本信息。
- 能修改场次信息。
- 能使用下拉框的字段应尽量使用下拉框，例如剧目、剧院、演员等。
- 下拉框内容来自已有基础数据，避免命名不统一。
- 修改后用户端展示内容能同步变化。

---

### 9.5 删除与撤销

管理员端中，能新增的数据应提供对应删除能力。

可检查内容：

- 剧目可以删除。
- 场次可以删除。
- 剧院可以删除。
- 演员可以删除。
- 餐馆可以删除。
- 交通方案可以删除。
- 支持批量删除部分数据，例如按剧目、场次或基础数据条目进行批量操作。

如果某些数据被其他表引用，系统可能会阻止删除或提示先删除关联数据，这属于正常的数据库完整性保护。

---

### 9.6 基础数据维护

进入基础数据维护区域。

可检查内容：

- 管理员可以新增剧院。
- 管理员可以新增演员。
- 管理员可以新增餐馆。
- 管理员可以新增交通方案。
- 上述基础数据也可以删除。
- 新增后的剧院、演员等能在新增场次或修改信息时作为下拉选项出现。

---

### 9.7 SQL 展示台

进入 SQL 展示台。

可检查内容：

- 页面介绍不包含“为答辩准备的安全查询区”等不合适表述。
- 大标题下简介应说明该页面用于数据库结构与数据状态检查。
- 页面列出多条常用数据库检测 SQL。
- 可用于查看表数据、视图结果、统计结果、数据联动情况等。
- 查询结果应以清晰表格形式展示。

## 10. 重点数据库验收点

本项目建议重点查看以下数据库能力：

1. 多表结构设计  
   包括用户、剧目、场次、演员、剧院、餐馆、交通方案、偏好、计划、记录等。

2. 关联查询  
   演出信息汇总、演员信息、剧院信息、推荐信息、行程信息均依赖多表关联。

3. 视图  
   用户侧的观演状态、演出信息、推荐辅助等内容可通过视图或封装查询体现。

4. 存储过程/触发器/约束  
   可检查用户计划、记录、删除、状态变更、数据完整性等逻辑。

5. 数据一致性  
   推荐页加入计划后，应联动到观剧日历与场景化行程辅助。

6. 权限与角色区分  
   普通用户和管理员登录后看到的界面与功能不同。

## 11. 常见问题处理

### 11.1 PowerShell 中 cd 报错

如果使用：

```powershell
cd /d D:\xxx
```

在 PowerShell 中可能会报错，因为 `/d` 是 cmd 的写法。

PowerShell 中应使用：

```powershell
cd "D:\xxx\项目文件夹"
```

---

### 11.2 运行后提示找不到数据库

请检查：

1. MySQL 是否启动。
2. `main_code.sql` 是否已经成功导入。
3. 页面侧边栏或 `secrets.toml` 中的数据库名是否正确。
4. MySQL 用户名和密码是否正确。

---

### 11.3 端口 8501 被占用

可以指定其他端口启动：

```powershell
streamlit run app.py --server.port 8502
```

---

### 11.4 依赖安装失败

可以先升级 pip：

```powershell
python -m pip install --upgrade pip
```

然后重新安装依赖：

```powershell
pip install -r requirements.txt
```

---

### 11.5 中文显示异常

建议确认：

1. 数据库字符集为 `utf8mb4`。
2. SQL 文件执行时没有被错误编码打开。
3. 浏览器使用现代版本 Chrome 或 Edge。
